# Kustos — резервные копии как в Time Machine

Kustos хранит историю домашней папки в зашифрованном, сжатом и
дедуплицированном репозитории формата restic. В окне виден таймлайн снимков,
любой из них можно просмотреть как в файловом менеджере и восстановить
отдельный файл, папку или целое дерево.

Движок — `rustic` (Rust, формат restic): шифрование AES-256, сжатие zstd,
дедупликация по содержимому. Приложение написано на Rust, интерфейс —
QML/Kirigami.

## Установка

```bash
sudo pacman -S qt6-base qt6-declarative kirigami qqc2-desktop-style rustic
cd ~/Projects/kustos
makepkg -si          # собирает из рабочего дерева и ставит пакет
```

После установки запустите одну копию (или откройте копию и задайте пароль для
просмотра): GUI сохранит credential, и расписание сможет работать без окна.
Юниты systemd при этом перезапишутся с новым `ExecStart=/usr/bin/kustos`.

## Первый запуск

- Репозиторий: `/data/Backup/kustos` (если `/data` доступна на запись).
- Одно правило **Home** с папками `~/.config`, `~/.local`, `~/Music`,
  `~/Pictures`, `~/Videos`, `~/.bashrc`, `~/.bash_profile`; расписание
  выключено.
- Исключения: `~/.local/share/Steam`, `~/.local/share/twintaillauncher`,
  `~/.local/share/Trash`.
- Хранение (общее для репозитория): почасовые за сутки, ежедневные за 30 дней,
  еженедельные за 12 недель.

Окно разделено на три колонки: **правила**, **снимки выбранного правила** и
**файлы выбранного снимка**. Клик по правилу фильтрует среднюю колонку, клик
по снимку открывает его справа. Контекстное меню правила (правый клик):
создать копию, остановить текущую, настроить, приостановить/включить или
удалить правило.

Кнопка **«Создать резервную копию»** в шапке окна запускает снимок по всем
включённым правилам. **«Настроить правило…»** открывает редактор правила,
выбранного слева: имя, папки/файлы, исключения и расписание; повторного списка
правил в диалоге нет, источники и исключения стоят рядом. Изменения
сохраняются сразу, а **«Сохранить»** закрывает редактор. Для заблокированного
правила сначала запрашивается пароль для просмотра. Тот же редактор
открывается из **Настройки → Настроить правило…**.

Снимки удалённого правила и старые снимки без метки правила не пропадают:
они собраны в пункте **«Другие копии»**.

## Пароли и блокировка

**Для запуска копии пароль не нужен.** GUI берёт сохранённый credential — тот
же, что использует служба systemd. Если репозитория ещё нет, генерируется
случайный ключ, репозиторий создаётся с ним, а ключ сохраняется как credential.
Пароль спрашивается только один раз — для старого репозитория, у которого
сохранённого credential нет; после этого он тоже сохраняется, и следующие
копии запускаются без вопросов.

**Пароль нужен для открытия копии (просмотра).** В
**Настройки → Безопасность → Пароли резервных копий** выберите режим:

- **у каждого правила свой пароль** — отдельный ключ `rustic`; открытие одного
  правила не открывает остальные;
- **один общий пароль** — один ключ привязывается ко всем правилам. Задание
  общего пароля создаёт новый ключ, обновляет все правила и все сохранённые
  credentials и сразу открывает все копии; при смене старый общий ключ
  удаляется.

Если у правила пароля ещё нет, при открытии предлагается его создать (или
создать общий); сохранённый credential разрешает это без ввода старого ключа.
Пароли правил задаются кнопкой **«Задать пароль…» / «Изменить пароль…»** в
редакторе, общий — в настройках. Все ключи открывают одни и те же данные
репозитория, поэтому это разделяет копии в интерфейсе, а не шифрует их
независимо; для полной изоляции нужны отдельные репозитории.

Пароли для просмотра хранятся только в памяти. Через время, выбранное в
**Настройки → Безопасность → «Блокировать после неактивности»** (в том числе
«Никогда»), они забываются; **«Заблокировать сейчас»** или `Ctrl+L` блокирует сразу. При
открытии заблокированной копии пароль спрашивается снова, а её снимки скрыты.
Копии при этом продолжают создаваться без пароля.

При переходе со старой версии с одним ключом репозитория первая копия без
сохранённого credential попросит старый ключ один раз (или это сделает
открытие копии). Затем ключ сохраняется как credential. Старый ключ остаётся
действительным, пока его ключ не удалён из репозитория.

## Правила копирования

Правило — это полное описание одной резервной копии:

- **Что копировать** — список папок и отдельных файлов; у каждого правила он
  свой. Несуществующие пути пропускаются с предупреждением.
- **Исключения** — пути внутри копируемых папок, имена папок и glob-шаблоны:
  `*.log`, `node_modules`, `~/.cache/**`. Шаблон можно ввести в поле и
  нажать «Добавить шаблон»; кнопка «Исключить папку…» добавляет выбранную
  папку. Исключения действуют только внутри этого правила.
- **Расписание** — выключено, «каждые N минут», «ежедневно в ЧЧ:ММ» или «по
  дням недели» с выбором дней. Для каждого правила с расписанием создаются
  отдельные служба и таймер systemd, поэтому правила могут запускаться в разное
  время. Расписание можно включить, когда у правила есть сохранённый
  credential: он появляется после первой копии или после задания пароля для
  просмотра.

Правил может быть несколько (например, «Документы» каждый час и «Фото» по
выходным). Правило можно поставить на паузу переключателем «Включено» —
ручной запуск при этом всё равно доступен.

## Пароли автоматических копий

Ключ правила (пароль для просмотра или сгенерированный ключ копии)
сохраняется для службы systemd в зашифрованном виде через
`systemd-creds --user`:
`~/.config/kustos/credentials/<id>.cred`. Служба загружает его как
`LoadCredentialEncrypted=`, поэтому приложение получает пароль из
`$CREDENTIALS_DIRECTORY/kustos-password` и может делать копию без открытого
окна. GUI использует тот же credential, поэтому копии запускаются без пароля,
даже когда снимки заблокированы. Если `systemd-creds` недоступен, используется
закрытый файл с правами 0600; редактор правила предупреждает об этом. В
`kustos.json` пароли не записываются.

Командная строка берёт пароль из `KUSTOS_PASSWORD`, `KUSTOS_PASSWORD_FILE` или
из `$CREDENTIALS_DIRECTORY/kustos-password`. Для нового репозитория пароль
обязателен: GUI создаёт репозиторий и credential автоматически, а CLI без GUI
нужен `KUSTOS_PASSWORD` или файл.

## Восстановление и сохранение копий

Выберите элементы в снимке и нажмите **«Восстановить…»**. По умолчанию файлы
возвращаются на исходное место; можно выбрать папку — тогда сохраняется вся
структура пути. Если файл уже существует: «Заменить», «Оставить существующий»
или «Сохранить оба» (копия получит имя `имя (restored <дата>)`).

Если файл или папку нужно просто **вытащить** из снимка, нажмите
**«Сохранить копии…»** или «Сохранить этот элемент…» в контекстном меню.
Откроется проводник, выберите папку — выбранные элементы будут скопированы
прямо в неё под своими именами, без длинного пути `home/user/...`. Одинаковые
имена не перезаписываются: новая копия получит суффикс `(restored <дата>)`.

Двойной щелчок по файлу (или пункт **«Открыть»** в контекстном меню) открывает
его в приложении по умолчанию, как в Dolphin. Перед этим файл распаковывается
во временную папку в `/tmp` с доступом только для пользователя; она
очищается при перезагрузке. Обычный щелчок только выбирает эту строку (не
открывает файл и не снимает выбор с уже выбранной строки); **Ctrl+щелчок**
переключает выбор для *«Сохранить копии…»*, *«Восстановить…»* или
*«Выбрать всё»*.

## Командная строка

```bash
kustos --backup                 # снимки по всем включённым правилам
kustos --backup --rule ID       # только одно правило
kustos --check                  # проверить структуру и индекс репозитория
kustos --check --read-data      # плюс случайные 10% данных
kustos --list                   # список снимков (с именем правила)
kustos --prune                  # применить политику хранения
kustos --restore <id> <путь>... [--to ПАПКА] [--policy overwrite|skip|keep_both]
kustos --print-config           # действующие настройки и правила

# CLI разблокирует репозиторий так же, как юниты systemd:
KUSTOS_PASSWORD=… kustos --list
```

Пути в `--restore` задаются относительно корня снимка, например
`home/soneriald/.config/kdeglobals`. `--print-config` печатает режим паролей, все правила с источниками,
исключениями, расписанием, временем блокировки и наличием пароля.

## Автоматические копии

Расписание задаётся у каждого правила отдельно в **«Правилах копирования…»**.
Для правила создаются пользовательские служба и таймер
`~/.config/systemd/user/kustos-backup-<id>.service` и `.timer`; служба
запускает `kustos --backup --rule <id> --quiet` и берёт пароль из
`~/.config/kustos/credentials/<id>.cred`. Интервальные правила используют
`OnUnitActiveSec` (первый запуск через 5 минут), ежедневные и недельные —
`OnCalendar`. Таймеры работают и при закрытом окне; правила без расписания или
без пароля юнитов не создают.

## Где что лежит

| Путь | Содержимое |
|---|---|
| `~/.config/kustos/kustos.json` | настройки (пароли не хранятся) |
| `~/.config/kustos/credentials/<id>.cred` | зашифрованный systemd-credential: ключ правила или сгенерированный ключ копии |
| `~/.cache/kustos/kustos.log` | журнал приложения |
| `/tmp/kustos-open-<uid>/` | временные файлы для «Открыть»; удаляются при перезагрузке |
| `~/.config/systemd/user/kustos-backup-<id>.service` | служба каждого правила |
| `~/.config/systemd/user/kustos-backup-<id>.timer` | таймер каждого правила |

Подробнее про формат — в [`docs/BACKUP-FORMAT.md`](../BACKUP-FORMAT.md).
